# Backend structure

The backend is a Node.js 22+ ESM application. `server.mjs` is the process entrypoint and application composition root. TypeScript modules under `src/` compile to the generated `build/` directory; ESM modules under `src/` are imported directly.

## Folders

```text
backend/
  server.mjs             HTTP server, request lifecycle, and application composition
  src/
    auth/                Neon Auth identity and cookie protocol helpers
    controllers/         HTTP request handlers grouped by domain
    infrastructure/      Database dialect and runtime infrastructure helpers
    integrations/        Jira, MCP, and Solari network adapters
    repositories/        Named, domain-scoped SQL operations
    routes/              Route-facing data operations used by the HTTP application
    sdk/                 Public Node.js client
    security/            Cookie policy and encrypted secret storage
    services/            AI, memory, and policy business logic
    utils/               Shared validation, HTTP, cookie, and context helpers
    *.ts                 Compatibility re-exports; keep new implementations out
  workflows/
    langgraph/           ReAct graph, tool registry, model adapter, runner, checkpointer
    snapshot-store.mjs   Durable workflow trace snapshots
  lib/                   JavaScript persistence/provider adapters, including TinyFish search and Solari browser sessions
  scripts/               Maintenance and operational scripts
  bin/                   CLI entrypoint
  build/                 Generated by the TypeScript build; do not edit by hand
```

## Placement and dependency rules

- Put request handling and HTTP response mapping in `src/controllers/`. Controllers receive their dependencies explicitly and delegate domain work to services and repositories.
- Put HTTP-specific route operations in `src/routes/`; keep provider protocol details out of route handlers.
- Put reusable application behavior in `src/services/`. Services should accept explicit inputs and return values rather than writing directly to the HTTP response.
- Put application SQL in `src/repositories/`, grouped by domain. Callers use named repository operations; SQL statements stay inside repository methods. Schema creation and migrations remain in `lib/db.mjs`.
- Put stateless shared helpers in `src/utils/`. Keep secrets, authorization, provider calls, and database operations out of generic utilities.
- Put third-party HTTP/API details in `src/integrations/` and database/runtime mechanics in `src/infrastructure/` or `lib/`.
- Keep auth and secret handling in `src/auth/` and `src/security/`.
- Keep the LangGraph pipeline and durable workflow trace code in `workflows/`.
- Add new code at its canonical path. The flat `src/*.ts` files only preserve existing compiled import paths while callers migrate to the grouped folders.

`server.mjs` is still the composition root and retains the central URL dispatch plus several legacy domain flows. System, authentication, employee-lifecycle, and background-job handlers have moved to `src/controllers/`; continue extracting the remaining route groups by domain. Application query call sites use domain repositories instead of issuing SQL directly.
